# Tic Tac Toe Showdown：轮流落子，先连成线者胜

## 一句话本质

表面上是井字棋的简单复刻；实际上核心机制是有限状态空间下的回合制博弈与胜负判定；本文重点解释如何用通用模块解耦棋盘规则与 AI 策略。

> 一句话本质：**轮流落子，先连成线者胜**。

## 这个游戏怎么玩

你要做的：和对手轮流行动，在棋盘格子里落子/摆放，让相同的连成一线。先把己方棋子连成规定长度的一线。

**行为循环**：状态流：boot → menu → gameplay → result；核心行为：轮流行动 + 放置落子 + 匹配连线 + 比较大小 + 做选择

## 规则只有三条，但足够深

- **轮流行动**
- **放置落子**
- **匹配连线**
- **比较大小**
- **做选择**

回合制棋盘的魅力在于：规则极简，但每一步都要想「我下这，对手下哪」。

| 参数 | 本游戏取值 | 可调范围 |
|---|---|---|
| playerCount | 2 | 1~4 |
| gridRows | 3 | 3~30 |
| gridCols | 3 | 3~30 |
| matchSize | 3 | 3~5 |
| directions | hv | - |
| threshold | 0 | - |

## 它是怎么拼出来的

这个游戏由 3 个公共模块组成：

- **common-ui**：通用 UI 事件绑定模块：自动为 skin 中的 button 节点绑定点击事件，并支持 boot 场景自动推进到 menu。
- **core/board-turn**：通用回合制棋盘核心：管理网格棋盘状态、落子、胜负判定（连线/连珠）。适用于井字棋、五子棋、四子棋、围棋简化版等棋盘玩法。
- **core/board-ai**：通用棋盘 AI：为 board-turn 提供落子决策。当前实现 minimax，支持井字棋等小规模零和棋盘游戏。

> 同一批模块换个规则，就是另一个游戏——这就是模块化的意义。

## 设计要点

- 3×3 小棋盘：状态空间有限，先手策略可穷举
- 连成 3 子即胜：进攻与堵截的平衡
- AI 强度 = 对手模型：随机/堵截/算杀三种体验

## 你能学到什么

- 棋盘类游戏的最小状态机（boot → menu → gameplay → result）
- 胜负判定如何写成纯函数（好测试、好复用）
- AI 对手其实就是「对手模型」的强度选择

## 边界条件

需要处理棋盘尺寸超出 3×3 时状态空间爆炸导致 AI 无法穷举的问题
需要处理玩家落子坐标越界或重复落子时的无效输入校验
需要处理棋盘填满后无连成线时的平局/结束状态判断
需要处理 AI 在无法必胜时选择堵截对手或随机落子的决策边界
需要处理游戏结束后玩家状态重置是否干净以避免残留数据

## 设计取舍

收益是规则极简且状态空间有限，代价是策略深度不足，替代方案是调整棋盘大小或连线长度来增加复杂度
收益是胜负判定写成纯函数易于测试复用，代价是 AI 强度完全依赖对手模型，替代方案是引入更复杂的启发式算法或评估函数
